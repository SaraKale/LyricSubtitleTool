# 双语字幕怎么处理

你问的「同一个时间码多个文字怎么排列」——这是 LRC 双语字幕最核心的一个问题。
这篇把几种常见做法、它们的坑，以及本项目怎么实现讲清楚。

---

## 一、先看清双语歌词的三种「数据形态」

不同来源的双语歌词，结构完全不一样，处理方式也必须不一样。

### 形态 1：单文件、同时间码重复

最常见的 LRC 双语格式，原文和译文各占一行，时间码完全相同：

```
[00:12.34]Hello, how are you
[00:12.34]你好吗
[00:15.10]I am fine
[00:15.10]我很好
```

**处理**：按时间码分组，同一组的多行合成**一个文字图层**（图层里是多行文本）。
这是最简单的，也最不容易出错。

### 形态 2：两个独立文件

`xxx.lrc`（原文） + `xxx.trans.lrc`（译文），各自有完整时间码。

```
原文： [00:12.34]Hello
译文： [00:12.35]你好
```

**坑**：时间码经常**差 0.01 ~ 0.3 秒**，甚至行数不相等（译文少一句）。
如果直接按「时间码相同就合并」，会拆成一堆单独的字幕。

**处理**：要做**配对（alignment）**，详见第三节。

### 形态 3：接口返回的原文 + 译文（网易云 / QQ 音乐）

网易云的 `tlyric`、QQ 的 `trans` 字段就是这个形态。本质上等同于形态 2，
而且偏差可能更大（网易云的译文时间码有时整体偏移）。

---

## 二、排版：合并成一个图层，还是各占一个图层？

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **上下两行**（推荐） | 一个文字图层，文本 = `原文\r译文` | 只有一个图层，统一控制位置/动画/样式；改样式一次搞定 | 两行样式只能相同 |
| **同一行拼接** | 文本 = `原文 / 译文` | 省垂直空间 | 一行太长会挤出画面；两种语言字号无法区分 |
| **两条独立图层** | 同一 in/out，两个图层 | 原文、译文可以分别用不同字体/大小/位置（比如小字号在下） | 图层数翻倍，位置要自己错开 |

**本项目的默认是「上下两行」**，因为它在 AE 里最好用：

- 图层数 = 字幕条数，不会翻倍
- 复制样式、打关键帧、加动画只需要对一个图层做
- 想分成两层也很容易，勾一下「同一时间码的多行各自单独建层」就变成两条独立图层

### 上下两行的排版细节

```
┌──────────────────────────┐
│       Hello, world       │   ← 原文，字号大
│         你好，世界         │   ← 译文，字号小
└──────────────────────────┘
```

AE 里就是个多行文本图层，用 `\r` 分隔：

```javascript
td.text = "Hello, world\r你好，世界";
```

想让两种语言**字号不同**，AE 的 `TextDocument` 做不到（它是整段统一样式），
两个办法：

1. **勾选「各自单独建层」**，生成两条图层，然后分别调样式（最省事）
2. 用 AE 24.3+ 的 `characterRange` / 逐字样式，或者手动在 AE 里调

### 竖排 + 双语

竖排时「上下两行」在视觉上会变成**左右两列**（中文竖排是从右往左读，所以原文在右、译文在左）。
如果语言习惯是「原文在右」，用默认的「原文在上」即可；否则在面板里切「译文在上」。

本项目的伪竖排实现会把每个 `\r` 当列分隔符，所以双语排出来天然是两列。

## 三、时间码配对算法（重点）

两个文件时间码对不齐时，怎么把译文正确地贴到原文上？

### 做法 A：按时间就近配对（本项目主方案）

```
对每一行译文：
    在还没被占用的原文里，找时间差最小的那一条
    如果最小差值 <= 容差（默认 0.6 秒）→ 配对成功，用【原文的时间码】
    否则 → 试按行号配对（仅当两边行数相同）
    再否则 → 这行译文单独成帧
```

几个取舍：

- **用原文的时间码**，不用译文的。原文的时间码通常是打轴打的，更准。
- **「已被占用」很重要**。否则「原文 A」可能同时被两行译文抢走。
- **容差默认 0.6 秒**。太小配不上，太大容易错配到隔壁句。
  网易云的译文偏差一般在 0.2s 以内，0.6s 是很稳的。
- **必配不上的**（比如译文多出来的注释行）单独成帧，而不是丢掉 —— 大不了手动删。

### 做法 B：纯按行号配对

```
译文第 i 行 ← 原文第 i 行
```

简单，但是**行数不一样时全错位**。所以本项目只把它当兜底（两边行数相同才用）。

### 做法 C：人工对齐界面

做一个左右两栏的表格让用户手动拖。最准，但工作量大，1.0 版没做。
本项目的做法是「自动配对 + 预览列表核对」，预览里能直接看到每帧内容，错了一眼就能发现。

## 四、时间轴上的几个细节

### 1. 相邻字幕留缝

```
[00:12.34] 上一句
[00:15.10] 下一句
```

如果直接设 `out = 15.10`，两句话会在 15.10 这一帧同时出现（上一句的最后一帧和下一句的第一帧重叠）。
所以本项目默认留 **0.02 秒**的缝（面板里「相邻间隙」）。

### 2. 太短的字幕要撑开

一句只有 0.15 秒的歌词，人眼根本看不清。默认「最短 0.3 秒」，低于这个值会被拉长。

### 3. 歌词一般比画面出现得早一点

人读歌词比听歌词慢，通常习惯字幕**提前 0.1~0.3 秒**出现。
面板里的「额外延后」填**负数**就是提前。这是人工微调项，按片子习惯定。

### 4. 纯文本没有时间码

「没有时间码的默认 2 秒按序列层排版」——本项目就是这么做的：
从 0 秒开始，每句 2 秒（面板里可改），首尾相接，中间留 0.02 秒缝。

## 五、本项目的实现位置

| 环节 | 文件 | 关键函数 |
| --- | --- | --- |
| LRC 解析（含元信息、offset、逐字标签清理） | `AE/src/03_lrc.jsx` | `SB.Lrc.parse` |
| 原文/译文配对 | `AE/src/03_lrc.jsx` | `SB.Lrc.pairBilingual` |
| 按时间码分组成帧、算 in/out | `AE/src/03_lrc.jsx` | `SB.Lrc.buildFrames` |
| 多行合并 / 拆分的实际落点 | `AE/src/03_lrc.jsx` | `buildLines` + `splitLines` 选项 |
| 写进 AE 图层 | `AE/src/04_layers.jsx` | `SB.Layers.applyTextToLayer` |

面板上对应的开关（「歌词导入」页 →「④ 时间轴与双语」）：

| 控件 | 作用 |
| --- | --- |
| 同时间码判定容差 | 时间差小于它就算「同一时间点」，合并成多行。默认 0.02s |
| 双语排版 | `上下两行` / `同一行` |
| 顺序 | `原文在上` / `译文在上` |
| 同一时间码的多行各自单独建层 | 勾上就不合并，一行一个图层 |
| 译文对齐容差 | 只在使用译文时生效，配对用的容差 |

### 在线获取双语歌词的完整链路

```
在线搜索（网易云/QQ）
   └→ 拿到 original(LRC) + translated(LRC)
        └→ SB.Lrc.pairBilingual(original, translated)
             └→ SB.Lrc.buildFrames(...)          → 帧列表
                  └→ SB.Layers.createTextLayers → AE 图层
```

也可以在面板上点「把歌词载入『歌词导入』页」，把歌词灌进文本框肉眼检查一遍再生成
—— 推荐这个流程，双语配错了肉眼能立刻发现。
