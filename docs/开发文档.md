# 歌词字幕排版工具（LyricSubtitleTool）· AE 版 / PR 版

一个从零写的字幕工具，**After Effects** 和 **Premiere Pro** 两端都有，共用同一套解析逻辑。

AE 端的三个核心功能：

1. **导入 LRC / 纯文本 → 批量生成字幕图层**
   支持标准 LRC 时间码、纯文本一行一句、双语（原文+译文）合并排版
2. **参考图层样式同步**
   把你调好的那个文字图层（样式 / 效果 / 关键帧 / 表达式 / 蒙版）一键套到其它图层，
   支持按图层号批量指定：`1-10`、`1,5,10`、`1-3,7,9-11`
3. **在线歌词搜索**
   网易云音乐 / QQ 音乐搜索，原文+译文双语歌词直接导入

PR 端（`PR_CEP/`）落地方式不一样，因为 PR 里没有「图层」这个概念，
字幕有两种做法，面板上都能用：

1. **字幕轨道**（推荐）
   歌词 → `.srt` → 导入项目 → `Sequence.createCaptionTrack()`，
   由 PR 自己铺成一条原生字幕轨。快、稳、不吃模板；
   样式归 PR 的「字幕样式」管，脚本改不了（PR 没给这个 API）。
2. **图形剪辑**（要自己控样式就用这个）
   在视频轨道上批量造文字剪辑，样式**完全继承你选的那个母版**。
   等于「Ctrl+C 复制一个调好样式的文字、Ctrl+V 贴 N 次、再逐个改字」的脚本版 ——
   字体 / 字号 / 颜色 / 描边 / 动画 / 位置一个字都不会跑。
   母版可以是：时间线上已有的剪辑（按坐标挑，**不依赖选中状态**）、
   时间线上当前选中的剪辑、项目面板里的图形素材、或一个 `.mogrt` 文件。
   后两种不依赖时间线，所以**空白序列也能直接生成**。

> 关于「PR 里复制粘贴图层，样式复制不过去」：不用复制样式。
> PR 的文字内容和样式都躺在剪辑的「基本图形」组件里，脚本能读写：
> `clip.getMGTComponent().properties` → 文字参数的值是一段 JSON
> （`textEditValue` / `fontEditValue` / `fontSizeEditValue` / `fontTextRunLength`），
> 只改 `textEditValue` 并同步长度，其余字段原样不动 —— 所以样式是被**继承**的，
> 不是被重建的。细节见 `PR_CEP/host/12_pr_graphics.jsx` 的文件头注释。

> ⚠ **PR 版的在线歌词为什么必须开 Node**：AE 的 ExtendScript 有 `system` 对象
> （`system.callSystem("curl …")`），PR **没有** —— 同一个调用在 PR 里直接报
> `ReferenceError: system is undefined`；而 ExtendScript 自己也做不了 HTTPS。
> 让面板的 Chromium 用 `fetch` 呢？CEP 11 起严格执行 CORS，网易云 / QQ 音乐的
> 接口都不返回 `Access-Control-Allow-Origin`，照样被拦。
> 所以 PR 版的 `manifest.xml` 里显式开了 `--enable-nodejs` + `--mixed-context`，
> 由面板的 Node 发请求（不受 CORS 约束），取回内容再喂给宿主缓存 ——
> 宿主那边是无状态的，面板把原动作**重放**一遍就命中缓存了。
> 链路：`client/net.js`（取网）+ `app.js` 的 `hostCall()`（重放）+
> `host/09_bridge.jsx` 的 `runWithFetch()` / `onlineDeliver`。
> 改完 manifest 必须**完全退出并重启 PR**，否则启动参数不生效。

## PR 版（Premiere Pro）怎么装

```bash
python _tools/build_PRCEP.py install
```

它会构建、复制到 `%APPDATA%\Adobe\CEP\extensions\LyricSubtitlePR`，
并自动打开 PlayerDebugMode（`HKCU\Software\Adobe\CSXS.11\PlayerDebugMode = 1`；
CSXS.9 / 10 / 12 也一并写上，多写不碍事）。

装完**重启 Premiere Pro**，在菜单 `窗口 > 扩展 > LyricSubtitleTool PR` 打开面板。

> 这次改过 `manifest.xml`（加了 `CEFCommandLine` 开 Node），所以升级后必须
> **完全退出 PR 再重开** —— 启动参数只在进程启动时读一次，光关面板不生效。
>
> **扩展菜单里看不到插件**时按顺序查：① 是否完全退出 PR 再重开；
> ② `HKCU\Software\Adobe\CSXS.11\PlayerDebugMode` 是否 = 1（REG_SZ）；
> ③ 目录是否是 `%APPDATA%\Adobe\CEP\extensions\LyricSubtitlePR\`；
> ④ 看 `%TEMP%\CEP11-PPRO.log` 里的 ERROR 行 —— CEP 拒绝加载扩展是**静默**的，
> 只有这个日志会说实话。
>
> 开发时踩过一次这个坑：manifest 的 XML 注释里写了 `--mixed-context`，
> 而 XML 规定注释不得包含连续两个减号 → 整个 manifest 非法 → 扩展直接消失，
> 日志里只有一行 `Comment must not contain '--' (double-hyphen)`。
> 现在 `build_AEJSX.py` 的 `check_xml()` 会在构建时拦住这种情况
> （AE 版 / PR 版都接了）。

手动装：把 `PR_AE_CEP/dist/LyricSubtitlePR` 整个文件夹拷到那个 extensions 目录，
再自己加注册表项。

单测（不需要开 PR）：

```bash
node tests/test_pr.js     # 宿主侧：时间换算 / 字幕轨 / 图形剪辑 / 选区兜底 / 空白序列 / 插入静默失败 / 文字写入 / 代取协议（220 项）
node tests/test_net.js    # 面板侧：取网层 + 读 .mogrt 参数（本地起 HTTP 服务，不依赖外网，43 项）
```

PR 端的使用说明和 AE 共用同一套 `README_*.html`（构建时复制进产物根目录，跟着扩展一起装）。

## 安装（AE 版）

### 方式一：一键装（推荐）

```bash
python _tools/install_ae.py
```

脚本会自动找到 AE 的 `Support Files\Scripts\ScriptUI Panels\` 目录并复制插件进去
（没权限时会提示改用管理员运行）。

### 方式二：手动装

把 `AE_JSX/歌词字幕排版工具.jsx` 复制到：

```
C:\Program Files\Adobe\Adobe After Effects 2023\Support Files\Scripts\ScriptUI Panels\
```

然后**重启 AE**。打开 AE 后在菜单 `窗口` 的最下面会多出「歌词字幕排版工具.jsx」，
点开就是一个可停靠的面板。

> 面板可以拖到右侧和「效果控件」之类并排停靠。
> 如果菜单里没有，检查文件是不是真的放进去了、以及扩展名是不是 `.jsx`（不是 `.jsx.txt`）。

### 方式三：不安装，直接用

菜单 `文件 > 脚本 > 运行脚本文件…` 选中 `AE_JSX/歌词字幕排版工具.jsx`，
会弹出一个浮动面板窗口，功能完全一样。

### 方式四：CEP 版（HTML 面板，**有真滚动条**，推荐）

```bash
python _tools/build_AECEP.py install
```

这条命令会做四件事：

1. 把 `00` / `01` / `02` / `02b~02e_i18n` / `03~06` / `08` + `AE_CEP/host/09_bridge.jsx`
   拆成 `AE_CEP/dist/LyricSubtitleTool/host/` 下的一堆独立 .jsx，由 bootstrap 逐个加载
2. 复制 `AE_CEP/client/`（含自动生成的 `i18n_en.js` / `i18n_zht.js` / `i18n_ja.js`）
   和 `CSXS/manifest.xml`，
   版本号从 `AE_JSX/src/00_header.jsx` 的 `SB.VERSION` 读，别的地方不再写死
3. 整个扩展目录复制到 `%APPDATA%\Adobe\CEP\extensions\LyricSubtitleTool_AE\`
   （用户级，**不用管理员权限**），顺手清掉改名前的 `SubtitleTool` 目录
4. 写注册表 `HKCU\Software\Adobe\CSXS.11\PlayerDebugMode = 1`（免签名加载的关键）

然后**重启 AE**，菜单 `窗口 > 扩展 > LyricSubtitleTool` 打开。界面是 HTML 写的，
有真正的滚动条、可以停靠、配色跟着 AE 的主题走。面板最右边的「设置」页可以在
中文 / English 之间切换。

> 装不上 / 面板空白时的排查顺序见文末「CEP 版排错」。
> ScriptUI 版和 CEP 版**互不影响**，可以两个都装着。

## 功能一：导入歌词生成字幕

### 支持的歌词格式

```lrc
[ti:歌名]          ← 元信息标签，会被识别（生成合成时会用作合成名）
[ar:歌手]
[offset:+500]      ← 毫秒偏移，会自动应用

[00:02.39]等等 我知道的啊
[00:04.23]这算不上些什么
[00:10.5]一位小数也行
[00:12.345]三位毫秒也行        ← 老脚本 P9 在这里会出 bug，本脚本没问题
[00:20][00:40]副歌重复的地方     ← 一行多个时间码
[00:30.00]字<00:30.5>幕<00:31>效  ← 逐字时间码会被清掉

这是一行没有时间码的歌词       ← 有时间码时会并入上一条字幕
```

**完全没有时间码的纯文本**：一行一句，从 0 秒开始，每句默认 2 秒（可改），顺序排布。

### 双语怎么办

LRC 双语最常见的是**同一个时间码写两行**：

```lrc
[00:12.34]Hello, how are you
[00:12.34]你好吗
```

CEP 面板的表单值存在 `localStorage` 里，下次开面板整体灌回去 —— 所以改 HTML 里的
`checked` / `selected` **对已经用过面板的机器没用**，会被那份旧存档盖掉。
`app.js` 里有一张 `FORM_DEFAULTS_CHANGED` 表 + `LS_FORM_VER` 版本号：
改了哪个控件的默认值，就把它写进那张表并把版本号 +1，首次加载时会强制套用新默认，
其余设置一概不动。

本脚本**默认（v2 起）**是**「原文 / 译文各占一个图层」**：一个时间码生成两个图层，
各自一行文字。想要合并回一个图层，改「双语图层」那一项即可：

| 面板选项（歌词导入 → ④ 时间轴与双语） | 效果 |
| --- | --- |
| 双语图层 = **原文 / 译文各占一个图层**（默认） | 一个时间码**两个**图层，各自一行文字 |
| 双语图层 = 合并到一个图层 | 一个时间码一个图层，`原文\r译文` |
| 双语排版 = 同一行 | 一个图层，`原文 / 译文`（拼成一行了，自然没法再拆，此时双语图层强制为合并） |
| 勾选「同一时间码的每行都单独建层」 | 每条独立成层，不限双语 |

**「各占一个图层」的两个坑，脚本已经处理好：**

1. **不会叠在一起。** 两个图层各自独立、Position 却是一样的，不处理就会严丝合缝地
   重叠、只看得见下面一层。所以拆出来的每一层都带 `sub`（组内序号）和 `subCount`
   （这组几个），生成时把整组当成一个块整体居中：

   ```
   原文  y = Y - step/2
   译文  y = Y + step/2        整组以面板上的 Y 为中心
   ```

   `step` 在「双语行距(px)」里填，留 `0` 就是自动 = **字号 × 1.25**。
   AE 的 Y 轴向下为正，`sub = 0` 排在上面，所以「原文在上 / 译文在上」那个下拉照样生效。

2. **顺序按诗句排，不会交叉。** 同一句的两层始终挨在一起：

   ```
   大好きなお洋服        ← 第 1 句 原文
   穿上最喜欢的洋服      ← 第 1 句 译文
   大好きなお化粧で      ← 第 2 句 原文
   搭配上最喜欢的妆      ← 第 2 句 译文
   ```

   预览列表里同一句的第二层会缩进，并带一个「原 / 译」角标，方便一眼核对。

用**模板图层**生成时也支持：模板可能带着位移动画，所以走「逐关键帧加 Y 偏移」，
不会把动画压成一个静态位置。

如果是**两个独立的 LRC 文件**（原文一个、译文一个），或者是在线接口返回的
原文+译文（时间码经常差 0.0x~0.3 秒），用面板上的「使用译文（双语）」+
「译文对齐容差」，脚本会做**智能配对**：按时间就近匹配，配不上再按行号匹配，
用的是原文的时间码。细节见 [`docs/双语字幕方案.md`](docs/双语字幕方案.md)。

### 自动居中

生成的每个文字图层都会用 `sourceRectAtTime` 读包围盒，然后反算 Position，
保证**文字块的中心**正好落在你指定的 (X, Y) 上。
不管是单行、五行、还是伪竖排都不会偏——这是很多老字幕脚本做不到的。

面板上的「位置居中」/「位置下方」按钮会按当前合成尺寸自动填好 X/Y。

### 竖排文字

- **AE 2024（24.2）及以上**：用原生 `lineOrientation`
- **AE 2023 及更早**：自动降级为「每个字后面插换行」的伪竖排，
  中英混排时连续的英文/数字会作为一个整体（`hello世界` → `hello` / `世` / `界`）

面板里可以选竖排方向（从右往左 / 从左往右）和竖排行距。

### 「歌词导入」页参数速查

| 参数 | 说明 |
| --- | --- |
| 无时间码时长(s) | 纯文本模式下每句占多久，也是带时间码时最后一句的时长。默认 2 |
| 相邻间隙(s) | 两条字幕之间的空档，避免上一句的尾巴和下一句重叠。默认 0.02 |
| 最短(s) | 太短的字幕会被撑到这个时长。默认 0.3 |
| 最长(s) | 大于 0 时限制单条最长时长，0 = 不限制 |
| 整体偏移(s) | 所有字幕整体前后平移 |
| 额外延后(s) | `leadIn`，字幕比时间码晚出现多少。填负数就是提前 |
| 提前结束(s) | `leadOut`，字幕提前多少结束 |
| 同时间码判定容差(s) | 时间差小于它就视为同一时间点 → 合并成多行。默认 0.02 |
| 图层名 | 歌词文本 / 序号 / 序号+歌词 |
| 图层颜色 | 给生成的图层打个标签色，方便一眼区分 |
| 生成后打包成预合成 | 生成完把新图层预合成，方便整体加效果 |
| **倒序导入** | 勾上后**最后一句排在最上层**（歌词3/歌词2/歌词1），默认是第一句在最上层。只改上下顺序，每句自己的入点出点不变 |

### ⑦ 模板图层（复制现有图层来生成）

> 这是推荐的做法，尤其是你已经在合成里做好了一个满意的样式时。

先在合成里手动做一个文字图层（字体、描边、图层样式、效果、文字动画器随便调，
调到满意为止），然后在 ⑦ 里点「用选中层」把它设为**模板**，再点「生成字幕图层」。

生成时不再走「新建 + 套样式」，而是**直接复制这个模板图层**
（`layer.duplicate()`，就是 Ctrl+D），只做三件事：

1. 把这一句的歌词写进去（只改 `text`，字体/描边/样式一律不动）
2. 入点出点设成这一句的时间
3. 关键帧从模板的时间范围**重映射**到这一句的时间范围（对时规则同上）

**为什么这招更靠谱**：`duplicate()` 是 AE 自己在内部复制，不走脚本 API，
所以**图层样式也能跟着走**——那正是脚本接口读不到、写不了的一块。
相比之下「样式同步」是一个属性一个属性地抄，AE 没开放的东西必然抄不到。

选项：
- **生成后隐藏模板图层**（默认勾）：模板本身不删，只是关掉显示，方便你回头改
- **图层名改成歌词**（默认勾）：不勾的话所有副本都叫模板的名字

## 功能二：样式同步（参考图层 → 目标图层）

这是最省事的一个功能。流程：

1. 在合成里把**一个**文字图层的字体、颜色、描边、位置动画、效果全部调好
2. 面板切到「样式同步」，点「取当前选中图层」把它设为参考图层
3. 在「图层号」里填 `1-10` 或 `1,5,10` 或 `全部`
4. 勾选要复制的内容，点「以参考图层重建」

### 图层号写法

| 写法 | 含义 |
| --- | --- |
| `1-10` | 第 1 到第 10 个图层 |
| `1,5,10` | 第 1、5、10 个图层（全角逗号也可以） |
| `1-3,7,9-11` | 混合写法 |
| `全部` 或 `*` | 合成里所有图层 |

图层号 = AE 图层栈里的序号，**1 是最上面那层**（和图层面板一致）。
默认会跳过参考图层本身，也可以勾掉「只处理文字图层」让它连其它图层一起处理。

**不确定填到几？** 输入框下面有一行实时提示，会直接告诉你：

```
本合成「字幕_初见」共 47 层；参考图层是第 1 层；本次覆盖 41 个（2-42）；还有 5 层没覆盖（43-47）
```

旁边的「**全部**」按钮一键填成 `1-47`。跑完之后结果框第一行也会再报一次总数，
漏掉的图层号会单独列出来并标 ⚠，不会出现「好像没全部处理」又说不清的情况。

### 能复制什么

| 选项 | 内容 | 备注 |
| --- | --- | --- |
| 文字样式 | 字体、字号、填充色、描边、行距、字距、对齐、仿粗斜、基线、横竖向缩放… | **默认保留各自的歌词文本**，不会被参考图层的文字覆盖 |
| 变换属性 | 锚点、位置、缩放、旋转、不透明度、倾斜 | 含关键帧 |
| 关键帧 | 打点、时间、值 | |
| 缓动与插值曲线 | 线性 / 贝塞尔 / 定格、缓入缓出、空间切线 | 复制运动感的关键 |
| 无关键帧时复制静态值 | 静态参数值 | |
| 表达式 | 属性上的表达式代码 | 连开关一起复制 |
| 效果 | 整条特效栈 + 每个参数的关键帧 | |
| 蒙版 | 蒙版路径（含关键帧）、模式、反转、羽化 | |
| 文字动画器 | 「动画 1 / 动画 2」里的属性动画 | |
| 图层属性 | 混合模式、3D 图层、运动模糊、折叠变换、自动定向、标签色 | |

### 复制不了什么（AE 的硬限制，别找了）

- **图层样式（Layer Styles）**——投影、外发光、描边那套。
  `layer.property("ADBE Layer Styles")` 能**读到个数**（所以日志里会报「还有 N 个图层样式」），
  但照着结构逐个属性重建会缺东西，靠不住。
  真要连它一起搬：**选中参考层 → 菜单「动画 > 将动画预设另存为」存成 `.ffx` →
  去「歌词导入」页 ⑥ 里选它套过去**（见下面「功能四」）。
  只想要描边的话，改用「文字属性 → 描边」或「效果 → 生成 → 描边」。
- **内容识别填充、Roto 笔刷** 的结果
- **父级关系**——不同合成里图层索引含义不同，盲抄会指向错误的图层
- **逐字不同的字符样式**（AE 24.3 之前没有 `characterRange` 接口）

另外：「文字样式」复制会**把整段文字统一成参考图层的样式**。
如果你的目标图层手动做过逐字调色，会被覆盖——这是 AE `TextDocument` 的语义决定的。

### 关键帧对时（重要）

复制关键帧抄的是**参考层的绝对时间**。参考层（第 5 层）的效果关键帧在 3.0s / 3.5s / 4.0s，
原样抄到第 1 层（入点 120s）上还是在 3.0s / 3.5s / 4.0s —— 于是整段动画落在这一层
可见范围之外，看上去就是「效果复制过去了但没反应 / 关键帧位置不对」。

所以抄完之后必须**重映射**到每个图层自己的入点/出点。选项在「关键帧对时」下拉框里：

| 选项 | 行为 | 什么时候用 |
| --- | --- | --- |
| **缩放到每层的入点/出点**（默认） | 把参考层的时长拉伸/压缩到目标层的时长 | 每句歌词长短不一时（字幕基本都是这种） |
| 整体平移，保持原节奏 | 只把整段动画挪到这一层的入点上，节奏长度不变 | 每句时长一样、只想换个起点 |
| 不处理（保留绝对时间） | 旧行为 | 想让所有层共用同一段绝对时间的动画 |

日志里会单独报一行「`关键帧对时：N 个`」，N 为 0 就是没搬动（选了「不处理」，或压根没关键帧）。

### 以参考图层重建（Ctrl+D 式）

样式同步页的主按钮是 **「以参考图层重建（Ctrl+D 式）」**（旁边那个「只同步文字样式」只管字体）。
它和「逐属性同步」那条老路的区别：

| | 逐属性同步（面板已隐藏） | 以参考图层重建 |
| --- | --- | --- |
| 做法 | 一个属性一个属性地抄 | `refLayer.duplicate()`，**AE 自己在内部复制** |
| 图层样式 | ❌ 抄不到 | ✅ 原样带走 |
| 效果 / 动画器 / 蒙版 / 表达式 | ✅ | ✅ |
| 父子关系 / 轨道遮罩 / 表达式引用 | ✅ 保留 | ❌ 目标层会被换掉 |
| 代价 | 无（非破坏性） | 旧图层删除，但可以 Ctrl+Z 撤销 |

重建时每层会保留自己的**文字**和**入点出点**，只把样式换成参考层的。
这一步是「图层样式也能跟着走」的唯一办法（.ffx 之外）。

> **为什么把「应用到目标图层」藏起来**：图层样式（投影 / 描边 / 外发光 / 斜面）AE 的脚本接口
> 根本没开放，逐属性抄必然漏，用户拿它做出来的字幕经常「样式没跟上」，效果明显不如重建。
> 代码没删（`doApplyStyle` / 宿主 `API.style`），恢复方法：
> CEP 版去掉 `AE_CEP/client/index.html` 里 `btnApply` 那行的 `style="display:none"`；
> ScriptUI 版把 `AE_JSX/src/07_ui.jsx` 里注释掉的两行 `R.btnApply = g4.add(...)` 取消注释，
> 并把 `onClick` 绑定那行的 `if (R.btnApply)` 去掉。

### 双语图层的样式同步（③ 双语图层）

选了参考层再点按钮，**默认会把参考层的 Position 也带过去**——
单语字幕没问题，双语就会翻车：原文层和译文层拿到了同一个 Y，严丝合缝叠在一起，
只看得见一层。样式同步页的 **③ 双语图层** 就是处理这个的，**两条路都认这组参数**
（`biScope / biPos / biStep / refLayer2`，判定都是 `LY.roleOf`）：

- **以参考图层重建**：复制出来的层就是参考层的位置，所以要按组内行号 `shiftLayerY` 挪回去；
  「完全不动位置」则把目标层自己那条 Position 整条 `copyProperty` 盖回去（要在
  `remapLayerKeys` **之后**，否则会被重映射带歪）。
- **逐属性同步（已隐藏）**：把 Position 从复制名单里摘掉，或者抄完再挪。

**先点「扫一遍分组」**，看脚本认出了几层、各归哪一组。判定有两条路：

| 优先级 | 依据 | 准不准 |
| --- | --- | --- |
| ① | 图层备注里的 `[ST]{...}` 标记（本脚本「各占一个图层」生成时写的） | 100% 准 |
| ② | 比文字体系：日文带假名 / 中文只有汉字，分得很干净 | 没标记时的兜底 |

备注里带标记的那批，判定结果会标「来自生成时的标记」。

认出分组之后，用 **「双语位置」** 决定位置怎么处理（默认已经是推荐值）：

| 双语位置 | 行为 | 什么时候用 |
| --- | --- | --- |
| **保留上下错位**（默认，推荐） | 样式照抄，但按组内行号把每组挪回它该在的高度 | 绝大多数情况 |
| 完全不动位置 | Position 直接不参与复制，各留各的 X/Y | 你已经手动摆好位置了 |
| 照抄参考层 | 老行为，两组会叠在一起 | 你就是要它们重叠 |

「保留上下错位」的行距默认 `0` = 自动（**字号 × 1.25**），和生成时那条规则一致；
想精确控制就在「行距(px)」里填数字。

另外两个常用组合：

- **「范围」= 只跟参考层同组 / 只另一组**：只想套原文、或只想套译文时选它，
  另一组一个图层都不会碰。
- **「另一组用」= 第二个参考层**：原文层和译文层样式本来就不一样（字号、颜色、字体
  都不同）时，给它指定译文的参考层，两组各抄各的，位置也各跟各的（此时不再做错位计算）。

跑完的日志里会写明：认出的同组 / 另一组各有几层、错开了几层、
用的是不是第二参考层。如果认出了两组却仍选「照抄参考层」，日志会**主动警告**两组会叠。

## 功能四：动画预设（⑥ 动画预设）

### 为什么要有这一块

从一个图层「深拷贝样式/动画」到另一个图层，有两个死穴：

1. 图层样式脚本搬不动（上面已说）；
2. **脚本 `addProperty("ADBE Text Animator")` 建出来的动画器是空壳** ——
   里面既没有动画器属性，也没有范围选择器。而「递归复制已存在的属性」
   对空壳一律失效，结果就是复制出几十个叫「动画器」的空壳：界面上有、动画没有。

所以这里换路子：**不拷贝，改为重建** —— 跟 P9 字幕脚本一个思路
（P9 自带 `动画预置.xml`，里面 15 套手写预设，生成图层时照着预设现场搭
「文字动画器 + 范围选择器 + 关键帧」）。

### 两条路

| | 内置预设 | 外部 `.ffx` |
| --- | --- | --- |
| 怎么用 | 下拉框直接选，开箱即用 | 把 `.ffx` 放进预设文件夹，点「刷新」 |
| 原理 | 脚本 `addProperty` 现场搭 | `layer.applyPreset(File(...))` 一步到位 |
| 能带图层样式吗 | 不能 | **能** —— `.ffx` 是 AE 自己的格式，不受脚本接口限制 |
| 依赖 | 无 | CC 2014+ |

内置 8 套：整句淡入淡出 / 整句模糊出入 / 逐字淡入（打字机）/ 逐字上划淡入 /
逐字模糊入 / 逐字缩放弹入 / 逐字旋转入 / 逐字下落入（带纵深）。

预设里的关键帧时间都写成 **0~1（相对于这一句的时长）**，套用时按每个图层自己的
入点出点换算 —— 所以长短句都能用同一套预设。

### 预设文件夹放哪

按顺序扫这三个地方（深度 2 层）：

1. `<AE安装目录>/Support Files/Scripts/ScriptUI Panels/预设/` ← 已自动建好
2. `<同上>/Presets/`
3. `<AE安装目录>/Support Files/Presets/`（AE 自带那堆）

也可以用面板里的「预设文件夹…」按钮自己指定一个目录（会记住）。

### 怎么把参考层的样式（含图层样式）存成 .ffx

1. 在时间轴里选中那个参考层
2. 菜单 **动画 > 将动画预设另存为…**（Animation > Save Animation Preset）
3. 存到上面的「预设」文件夹里
4. 回面板点 ⑥ 里的「刷新」，下拉框里 `[ffx] xxx` 就是它

### 生成时自动套

⑥ 里勾上「生成字幕时自动套用」，生成字幕图层时会顺手套一遍
（在打包预合成**之前**做，否则图层进了预合成就不好改了）。

## 功能三：在线歌词搜索

1. 「在线歌词」页选平台（网易云音乐 / QQ 音乐），输入歌名或歌手，点「搜索」
2. 列表里选中一首，点「获取歌词（含译文）」
3. 下方会显示原文和译文，点「把歌词载入『歌词导入』页」
4. 切回「歌词导入」页，**肉眼核对一下**（尤其是双语配对），再点「生成字幕图层」

也支持**直接粘贴歌曲链接或 ID**：

- 网易云：`https://music.163.com/#/song?id=xxxxxxx` 或直接填纯数字 ID
- QQ 音乐：`https://y.qq.com/n/ryqq/songDetail/xxxxxxxxxxxxx` 或直接填 songmid

### 技术实现说明

ExtendScript 既没有 `XMLHttpRequest` 也没法直接做 HTTPS，所以走的是：

```
system.callSystem() → C:\Windows\System32\curl.exe → 下载到临时文件
                   → File + 编码自动识别读回来 → 自实现的 JSON 解析器
```

- Windows 10 1803+ / Windows 11 自带 `curl.exe`，macOS 自带 `/usr/bin/curl`
- 找不到 curl 时自动降级到 PowerShell 的 `Invoke-WebRequest`
- 「关于 / 自检」页能看到当前用的是哪个通道

接口来源参考了 `MMT Subtitle Editor`（`E:\MMDTools\插件项目\MMD SubtitlesLyric GUI`）：

| 用途 | 接口 |
| --- | --- |
| 网易云搜索 | `music.163.com/api/search/get?s=<kw>&type=1&limit=30` |
| 网易云歌词 | `music.163.com/api/song/lyric?os=pc&id=<id>&lv=-1&tv=-1` |
| QQ 搜索 | `c.y.qq.com/soso/fcgi-bin/client_search_cp?w=<kw>&format=json&new_json=1` |
| QQ 歌词 | `c.y.qq.com/lyric/fcgi-bin/fcg_query_lyric_new.fcg?songmid=<mid>&nobase64=1` |

> 这些是非官方接口，平台改策略就可能失效。真失效了看 `06_online.jsx` 里的 URL 改一下即可，
> 搜索失败不影响前两个功能（手动粘贴歌词永远能用）。

## 编码问题（中文歌词必看）

网上的 LRC 文件编码很乱：UTF-8、UTF-8 with BOM、GBK、GB2312、BIG5 都有。
读错编码的表现就是**一整屏乱码**。

本脚本做了两件事：

1. **自动识别**：先按 UTF-8 严格校验（GBK 的中文字节序列几乎必然违反 UTF-8 规则），
   不通过就依次尝试 GBK / GB18030 / GB2312 / BIG5 / Shift-JIS
2. **手动兜底**：面板上「编码」下拉可以强制指定。自动识别错了就切一下

还乱码的话，用记事本打开 LRC → 另存为 → 编码选 UTF-8，再导入。
如果连文件都不想要，直接在面板文本框里手动粘贴（Ctrl+V），彻底绕开编码问题。

## 开发

### 改代码

改 `AE_JSX/src/*.jsx`，然后重新构建：

```bash
python _tools/build_AEJSX.py
```

构建脚本会做四件事：

1. 按顺序把模块拼成单文件 `AE_JSX/歌词字幕排版工具.jsx`
2. **ES3 兼容检查**——扫 `let` / `const` / `=>` / `` ` `` / `Object.keys` / `Array.includes`
   / **原生 `JSON.parse` / `JSON.stringify`** / ES3 保留字当变量名 之类 ExtendScript
   会直接报错的写法

   > ExtendScript **没有** JSON 对象，一律用项目自带的 `SB.JSON.parse` / `SB.JSON.stringify`
   > （`AE_JSX/src/01_json.jsx` 里挂上去的）。写顺手写成 `JSON.stringify` 不会被 `node --check`
   > 拦下，到了 AE 里才炸，所以专门加了这条规则。写 `SB.JSON.` 前缀才放行。
3. **正则检查**——扫正则字符类里未转义的 `/`（见下）
4. **语法检查**（`node --check`，剥掉 `#target` 这类预处理指令后跑）

输出文件写成 **UTF-8 with BOM**。这一步很关键：ExtendScript 靠 BOM 判断源码是 UTF-8，
没有 BOM 的话 AE 会按系统 ANSI 解析，面板上的中文全变乱码。

> **为什么要单独查正则里的 `/`**：`node --check` 查不出来（标准 JS 允许字符类里写 `/`），
> 但 ExtendScript 的旧词法分析器会把 `/` 当成正则结束符，最终报出
> `ReferenceError: 无法显示在分配的左边，因为它为只读`——报错信息和实际内容完全对不上。
> 详见 [`docs/AE脚本开发入门.md`](docs/AE脚本开发入门.md) 第 11 节。

### 多语言（i18n）

界面文案和脚本日志走同一张**中文原文当 key** 的字典，四种语言共用同一套 key：
简体中文（不查表，恒等）、繁体中文、English、日本語。
好处是改文案不会出现「忘了改 key」的漂移 —— 因为根本没有 key，中文原文自己就是 key。

```
_tools/i18n/ui.json     面板 HTML（index.html 的 data-i18n）  ┐
_tools/i18n/app.json    前端 app.js 的文案                    ├─ 英文译文（人工维护）
_tools/i18n/host.json   宿主 ExtendScript（02~08 + 09_bridge）┘
_tools/i18n/zht.json    繁体译文（gen_zht.py 自动生成，别手改）
_tools/i18n/ja.json     日文译文（人工维护）
_tools/i18n/expr.json   批量改写规则（wrap / pairs），只在改造源码时才用得上
        │
        ├─ _tools/build_i18n.py ──→ AE_CEP/client/i18n_en.js    （window.I18N_EN）
        │                          AE_CEP/client/i18n_zht.js   （window.I18N_ZH_HANT）
        │                          AE_CEP/client/i18n_ja.js    （window.I18N_JA）
        │                          AE_JSX/src/02b_i18n.jsx      （核心：SB.M / SB.T / setLang）
        │                          AE_JSX/src/02c_i18n_en.jsx   （英文表）
        │                          AE_JSX/src/02d_i18n_zht.jsx  （繁体表）
        │                          AE_JSX/src/02e_i18n_ja.jsx   （日文表）
        ├─ _tools/gen_zht.py ────→ _tools/i18n/zht.json     （简→繁字形转换 + AE 术语修正）
        └─ _tools/i18n_audit.py ─→ 体检：裸中文 / 缺译文 / 英文栏残留中文
```

**宿主侧为什么是 4 个文件**：一张表 55~70KB，四张塞进同一个 .jsx 就是 ~180KB，
而 ExtendScript 单个编译单元只有 ~107KB 的余量 —— 塞一起必然报「语法错误」，
而且报错行号会指到别处的代码。所以表各自成文件，由 `SB.addTable()` 挂进去。
ScriptUI 版不做语言切换，因此 `build_AEJSX.py` 的 `ORDER` 只带 `02b`（3.7KB 的核心），
三张表只有 CEP 版才需要。

```bash
python _tools/build_i18n.py             # 重新生成全部产物
python _tools/build_i18n.py --check     # 校验：译文冲突 / 各语言缺词 / 没人用的 key
python _tools/gen_zht.py                # 只重生成繁体表（需要 zhconv）
python _tools/i18n_audit.py --strict    # 体检：裸中文 / 接了查表但没译文 / 残留中文
```

加一种语言要同时动四处：① `_tools/i18n/<lang>.json` ② `build_i18n.py` 的 `LANGS`
③ `index.html` 的 `<script>` 和下拉 `option` ④ `build_AECEP.py` 的 `CLIENT_FILES`。
`tests/test_i18n.js` 会校验四种语言的 key 集合一致，漏一处就会红。

几条踩过坑的约定：

- **所有 `02x_i18n_*.jsx` 和 `i18n_*.js` 都是自动生成的，不要手改**。
  改译文改 `_tools/i18n/*.json`，改中文改源码里的原文 —— 两边都不需要同步 key。
- `02b_i18n.jsx` 必须排在所有调用 `SB.M()` 的模块**前面**。`build_AEJSX.py` 和
  `build_AECEP.py` 的 `ORDER` 里有它，`tests/test_logic.js` 的 `MODULES` 里也有 ——
  少一处，那个产物一跑就是 `SB.M is not a function`。
- **接口值不能用中文**：下拉框的 `value` 一律用跨语言不变的 ASCII id
  （编码是 `auto`/`utf8`/`gbk`…，标签色用下标），
  只有给人看的 `label` 才翻。否则切一次语言，面板回传给宿主的值就对不上了。
- **数据表不在声明处翻**：`LY.LABELS`（标签色名）、`PR.BUILTIN`（预设名）、
  `ON.PLATFORMS`（平台名）、`U.ENCODING_LABELS` 这些是**数据**，
  声明处用 `/* i18n-allow */ … /* i18n-allow-end */` 标起来，
  到桥接层用 `SB.T()` / `SB.TList()` **在用到的那一刻才翻** ——
  在声明处翻会被「模块只在加载时求值一次」卡住，用户切语言时切不动。
- 前端切语言要做三件事，少一件就会「一半中文一半英文」：
  ① 静态文案（`data-i18n`）重铺 ② 运行时拼出来的重刷（下拉框、提示、版本串）
  ③ 通知宿主（`API.setLang`，它那边的 `SB.lang` 管运行日志和错误信息）。
- ScriptUI 版（`07_ui.jsx`）不参与多语言 —— 用户明确只要 CEP 面板。
  体检脚本会把它单独列出来，但不计入「需要处理」。

### 报错看不懂的时候

ExtendScript 的报错经常是废的（没有行号，或者行号对不上内容）。这时用源码定位器：

```bash
python _tools/run_ae_selftest.py --script tests/ae/ae_diag.jsx

它算出源码的括号深度表，挑出「括号配平 + 不在注释里 + 以 `;`/`}` 收尾」的位置做切点，

并且**一边跑一边写报告**，所以就算中途把 AE 搞崩了，也能看到崩在哪一步。

### 面板 UI：折叠分组与单开模式（以及为什么没有滚动条）

「歌词导入」页的 ①~⑦ 七块内容都做成了**可折叠分组**（标题栏就是按钮，▼/▶ 表示
展开/折叠），顶部还有「全部展开 / 全部折叠」两个快捷键，再加一个 **「单开模式」**
（默认开：展开一块时自动收起其它块，整个面板就永远只有一块高）。折叠状态会记住，
下次开 AE 还是上次的样子。

面板高度**自动贴合内容**：折叠完窗口会跟着收矮，不会在底下留一大片空白。
想再多留点空就用右下角的「＋ −」（每次 60px），这块留白记在设置里，折叠分组不会被吞掉。

**滚动条做不出来**，这是 AE 2023 的 ScriptUI 的硬限制，不是没做（详见
`AE_JSX/src/07_ui.jsx` 文件头注释）：

| 想用的办法 | 实测结果 |
| --- | --- |
| `visible = false` 收缩布局 | ❌ 不画了但位置还占着，面板一点不变短 |
| `scrollbar` 控件 | ❌ 是横向的，`orientation = "vertical"` 不生效（仍是 120×16） |
| `stack` 分组 + 手动改 `location` 滚动 | ❌ `location` 在下一次 `layout()` 会被重置回 `(0,0)`；且 stack 分组不 `fill`（宽度算成 -1，位置飘到中间） |
| 固定高视口 + 内容上移 | ❌ 超出的内容**不会被裁掉**，会糊到下面的控件上 |

所以折叠走的是「把容器的高度压到 0」这条路，其中有个**很坑的坑**：

| 现象 | 说明 |
| --- | --- |
| 尺寸赋值顺序 | 必须 `preferredSize` → `minimumSize` → `maximumSize`，且 `maximumSize` 的宽要给**大数**（如 10000）；写成当前面板宽度会**静默失效** |
| 「还原成自动高度」做不到 | 三个值设回 `-1` **不会**恢复按内容自动算：`preferredSize` 会永远停在 `2147483648` 这个哨兵值上，`size.height` 从此恒为 `-1` |
| 所以折叠/展开全靠记下来的高度 | 展开时必须用折叠前量到的数字显式撑回去 |
| 高度怎么量 | 先让布局按自然状态跑一遍，读 `body.size.height`；读不到（-1）就按子控件的 `size.height` 求和 + 间距 |
| **光压 `body` 还不够** | 外层 `wrap`（panel）会留着自己折叠前的高度 → 症状是「**初次启动各分组之间空一大截，手动点一下『全部折叠』就又正常了**」。所以 `wrap` 的高度也要钉：展开 = 量到的整高 `wrapH`，折叠 = 标题栏 + 边距（`baseWrapHeight`），两个方向都要钉，只钉一边就永远回不去了 |
| **首屏那一次布局算不干净** | `win.show()` 之后马上改尺寸，AE 还没进入上屏状态。`settleLayout()` 会用 `app.scheduleTask` 推迟 60ms 再「量一遍 + 套状态 + 重排」兜一次（拿不到闭包，所以定时任务字符串里通过全局 `SB.UI.__settle` 摸回来） |
| 浮窗高度要自己收 | 折叠之后窗口不会跟着变矮，`fitWindowHeight()` 按各子控件高度之和收一次（只在明显偏高时动手，并多留 30px 余量，免得把底部状态栏切掉） |

## CEP 版面板（HTML + 真滚动条）

### 为什么还是做了

ScriptUI **做不出**滚动容器（上文那张表全是实测结论），而选项一多就得滚。
CEP 面板是内嵌的 Chromium，`overflow: auto` 就是原生滚动条，CSS 排版、
停靠、主题跟随全都白送。所以最终做成了两套面板：

| | ScriptUI 版（`AE_JSX/歌词字幕排版工具.jsx`） | CEP 版（`CEP/`） |
| --- | --- | --- |
| 界面 | ExtendScript 老控件 | HTML + CSS（`AE_CEP/client/`） |
| 滚动条 | ❌ 做不出 | ✅ 原生滚动条 |
| 安装 | 复制一个 `.jsx` | `python _tools/build_AECEP.py install` |
| 停靠 | 可停靠 | 可停靠，位置由 AE 记住 |
| 逻辑层 | 同一套 `01~06` + `08` | **同一套** `01~06` + `08` |
| 界面层 | `07_ui.jsx` | `AE_CEP/host/09_bridge.jsx` + `AE_CEP/client/*` |

**装完 CEP 版不用删 ScriptUI 版**，两个可以同时用 —— 万一 CEP 加载失败，
还有个能用。

**分组折叠**：「歌词导入」页顶部有 `全部展开 / 全部折叠`，还有一个
`同时展开多块` 的勾（**默认勾着**）。不勾就是「单开模式」—— 展开一块会自动收起其它块。
每块的展开状态单独记在 `localStorage` 里，下次开 AE 还是上次的排布。

**「取当前选中图层」按钮**（样式同步页 / 模板图层页各一个）取的是时间轴里的选中项。
AE 的选中状态是**跟合成绑在一起的**，而且 `comp.selectedLayers` 在某些版本/场景下
会返回空数组，所以宿主里做了兜底：先读 `selectedLayers`，读不到就逐层查
`layer.selected`；下拉框选的合成跟正在看的合成不是同一个时，会自动切过去并把
下拉框同步好。真没选中时弹窗会明确告诉你「点一下时间轴里的图层名字」。

│        JSON 字符串      │◀───────────────┼──▶  分发到 API[action]     │
└────────────────────────┘   JSON 字符串   │      ↓                     │
                                           │   01~06 / 08（原样复用）    │
                                           └────────────────────────────┘
```

> ⚠️ **宿主入口名必须跟前端对得上。** 桥接层里定义的是 `BR.invoke`，
> 挂出去的是 `root.Bridge = BR`，所以真正能调的是 **`SB.Bridge.invoke`**。
> 文件末尾又补了个短别名 `root.invoke = BR.invoke`，`SB.invoke(...)` 也能用。
> 少了这个别名，前端每一次 `evalScript` 都会因为「SB.invoke 不是函数」
> 拿到 `EvalScript error.`，**所有按钮统一报「返回内容不是合法 JSON」**——
> 这个现象很有迷惑性：看着像 JSON 转义坏了，其实是入口名根本没挂上。

### 三个必须注意的点（都是踩过的坑）

**1. 字符串要转义两次。** `evalScript` 传的是 ExtendScript **源码**，
所以 JSON 里的 `\`（Windows 路径、歌词换行）和 `"` 都得再转义一层，
否则传到宿主那边就散了：

```javascript
function escJson(s) { return s.replace(/\\/g, "\\\\").replace(/"/g, "\\\""); }
cs.evalScript('SB.Bridge.invoke("preview", "' + escJson(JSON.stringify(args)) + '")', cb);
```

**1b. 别假设宿主脚本一定已经在那儿。** 理论上 `manifest.xml` 的 `<ScriptPath>`
会在面板加载时自动执行 `host/index.jsx`，但这环一断（引擎被换掉、扩展被重载、
或者拿别的方式打开的面板），`SB` 就不存在，`evalScript` 会返回
`EvalScript error.`。所以 `app.js` 的 `call()` 前面带了段引导前缀，
发现 `SB.Bridge` 不在就当场 `$.evalFile` 拉起来，并且失败时自动重试一次：

```javascript
'if (typeof SB === "undefined" || !SB.Bridge) { $.evalFile("' +
    extRoot + '/host/index.jsx"); }\n' +
'SB.Bridge.invoke("preview", "...")'
```

路径要用 `cs.getSystemPath(SystemPath.EXTENSION)` 拿，并统一成正斜杠 ——
ExtendScript 在 Windows 上也认 `/`，正好省掉一层反斜杠转义。

**2. 宿主里别弹模态框。** ExtendScript 的 `confirm()` / `alert()` 在 CEP 里
会弹到 AE 主窗口后面，用户根本看不见，表现就是「点了没反应然后卡住」。
所以「合成要不要加长」「重建要不要继续」都是宿主返回 `needConfirm`，
由 HTML 弹窗，拿到答案再带着 `extend` / `confirmed` 调一次。

**3. 进度靠轮询，但面板不会卡死。** 宿主跑长任务是同步阻塞的，
进度消息写进宿主的 `BR.state.log`，前端每 300ms 调一次 `log` 动作取走。
注意 ExtendScript 引擎是**单线程**的 —— 任务跑完之前后来的 `evalScript`
都排在队里，所以进度实际是任务结束后一次性回收。
真正的收益是：Chromium 那边的界面线程跟 AE 是分开的，
**生成 46 层的时候面板照样能滚能点**，不会再出现 ScriptUI 那种
「点了之后面板卡死、窗口被推到后台」的情况。

### CEP 版排错

| 现象 | 检查 |
| --- | --- |
| 菜单 `窗口 > 扩展` 里没有「LyricSubtitleTool」 | ① 重启过 AE 没有；② `HKCU\Software\Adobe\CSXS.11\PlayerDebugMode` 是不是 `"1"`；③ 目录是不是真的在 `%APPDATA%\Adobe\CEP\extensions\LyricSubtitleTool_AE\` |
| 面板出来了但是一片空白 | 打开 <http://localhost:8088> 用 DevTools 看 Console；八成是 `manifest.xml` 里的 `MainPath` 路径或 `RequiredRuntime` 版本对不上 |
| 面板能开但一点按钮就报「不是合法 JSON」 | 先看面板底部状态栏的**启动自检**那行：写「宿主已就绪」说明桥是通的，那就是单个动作里抛异常；写「宿主脚本没加载」/「SB.Bridge.invoke 不在」就是入口没挂上（重新 `build_AECEP.py install`）。细节看 DevTools Console，或在 `BR.invoke` 里 `$.writeln` 打一下 |
| 想看宿主的日志 | DevTools Console 里直接敲 `new CSInterface().evalScript('SB.Bridge.invoke("selfTest","{}")', alert)` |

`.debug` 文件（已在产物里）会把调试端口开在 8088，正式分发时删掉它就行。
